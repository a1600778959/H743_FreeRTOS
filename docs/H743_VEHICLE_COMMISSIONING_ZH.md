# Dima H743 FreeRTOS Rover 上车部署与操作指南

适用对象：当前工程的 STM32H743 差速车辆；以两侧可逆 PWM 电机、SBUS 遥控、UM982 双天线 GNSS 和可选 DroneCAN 磁力计为主要配置。

核对日期：2026-09-28。源码基线为工作区 `HEAD=8ccfc4e` **加当时尚未提交的修改**，不能仅凭该提交号复现全部行为。本指南依据当前源码、权威参数定义和正式生成元数据编写；没有对某一台车完成烧录、波形测量或道路验收。

**实际顺序：硬件与断动力检查 → 固件身份及参数备份 → 通信与 RC 配置 → PWM 中位/侧别/方向验收 → 传感器安装与基础校准 → 低速手动路试 → 自动校准 → 保存及重启回读 → 简单 Mission → 扩大工况。前一阶段未通过，不进入后一阶段。**

## 1. 开始前先明确的边界

1. **自动校准会真实开车。** 当前正式制动测量会达到 `MOT_THR_MAX` 对应的全输出，持续取得观测后执行有界反向驱动制动；这段实验允许超过 `RO_SPEED_LIM`。把巡航速度设低，不等于整场自动校准都低速。
2. **直线与转圈有不同空间约束。** `RO_CAL_DIST` 是直线目标距离；`RO_CAL_RADIUS` 约束转圈及二维路径。直线不受后者裁短。两者参考本次入场固定 GNSS 点，不能把半径参数理解成整车全程绝不会越过的物理安全围栏。
3. **Manual 解锁不替代上车检查。** 当前基础预检主要检查左右电机功能已分配；摇杆居中、传感器标定、实际电机方向和电调停止中位仍要由操作员确认。运行期 RC 丢失、执行器故障等保护继续有效。
4. **上锁与急停的电气行为不同。** 普通 Disarmed 对有效 PWM 通道输出 `CENT`；Kill、故障、失效及校准停波窗口会停止脉冲。电调必须分别验证“中位停止”和“无信号停止”。撤掉驱动力不等于机械制动，坡面仍可能溜车。
5. **RC 是当前手动控制来源。** USB/数传连接 QGC 不等于已具有遥控接管能力。当前 RC loss 策略是 Disarm；地面站数据链丢失不触发自动返航。低电量兼容项也没有已实现的自动处置动作。
6. **默认参数不是整车调校结果。** 默认轮距、若干速度/转向增益为零；即使可以进入 Mission，也可能因控制配置不完整而保持停波。
7. **指南中的示例只是操作示例。** 轮距、电调中位、正反向、天线基线、杆臂、输出上限必须来自本车测量；不能整段照抄成可导入参数文件。

## 2. 如何使用参数资料

### 2.1 唯一目录与正式生成

参数名称、类型、默认值、取值范围、枚举、只读属性和重启要求，以项目工具生成的目录及同版固件提供给 QGC 的 Metadata 为准。本指南只说明操作中涉及的参数，不维护另一份完整参数表、消息表或导入模板。

在 Windows PowerShell 中执行：


生成结果可直接打开：

- [正式参数 JSON](../build/generated/parameters/parameters.json)
- [正式参数 XML](../build/generated/parameters/parameters.xml)
- [QGC 参数 Metadata](../build/generated/component_metadata/parameters.json)
- [QGC 执行器 Metadata](../build/generated/component_metadata/actuators.json)

这些文件在构建目录中，清理后需要重新生成，禁止人工编辑。2026-09-28 本次正式入口执行成功，目录包含 301 个参数；这个数字只是本次快照，不是后续版本的固定要求。

### 2.2 “必须设置”的三种含义

**人工必配/必核对**：涉及本车接线、方向、几何或实验范围，必须逐项核对；已有正确值可以保留。第 5～9 节在具体操作中说明。

**由校准产生**：设备 ID、传感器 offset/scale、动力学和控制增益等应由相应校准或有证据的整定产生。不可随便填一个非零值来消除未就绪提示。

**有默认值但必须验证效果**：超时、换向等待、输出斜率、航点半径等，可从当前默认开始；是否适合本车由实测决定。协议允许写入的范围，也不保证满足各运行模式更严格的组合要求。

每轮参数修改遵循：**Disarmed → 修改 → 重新读取确认 → 等待存储完成 → 按 Metadata 重启 → 再读取 → 做对应动作检查**。MAVLink 回显只证明 RAM 已接受，不能证明掉电持久化。车辆 Armed 或校准过程中不要批量修改参数。

## 3. 硬件准备与现场记录

### 3.1 首次通电前

- 将车轮可靠架空；首轮只给控制器和传感器供电，电机动力保持断开。架车装置不能因转向或振动倾倒。
- 核对控制板、接收机、GNSS、CAN 外设、电调的供电范围、电平和共地。UART 接口不能直接接入 RS232 电平；连接器电源脚以本板原理图和丝印实测为准。
- 明确车头，并从**车尾朝车头**确定左、右。给每条电机信号线标记 PWM 插口和真实侧别。
- 核对电调支持双向中位控制，了解其上电学习、失信号行为和反向制动限制。单向油门电调或需要独立方向脚的驱动器不能仅靠参数冒充本项目的可逆 PWM 后端。
- 准备独立可操作的动力断电方式；Kill 开关用于固件链路急停，不能代替硬件断电装置。
- 检查 CAN 线序、两端终端电阻、节点电源和线束固定；测量总线终端时先断电。
- 固定 IMU、双天线及磁力计，远离电机强磁场和大电流回路，避免天线相对位置随车辆运动改变。
- 插入已确认可正常挂载、有剩余空间的 SD 卡。控制器无卡并不等于完全不能运行，但首轮上车应保留 ULog 和可靠的任务/参数备份条件。

### 3.2 建立本车记录

记录车号、控制板版本、固件身份与日期、电调型号、供电电压、轮胎和负载、左右信号插口、接收机型号、遥控通道用途、GNSS 飞控端口与接收机端口、双天线位置、磁力计型号/位置、实测轮距、测试场地及负责人。

另保存：部署前参数导出、各阶段参数导出、任务文件、ULog、QGC 文本日志、关键动作录像和 PWM 测量结果。源码结论、构建结果与实车记录分别保留。

## 4. 固件部署与第一次连接

### 4.1 构建

正式构建使用 Windows 原生工具链：

```powershell
Set-Location E:\freertos\H743_FreeRTOS
& C:\Users\master\.local\bin\make.cmd NO_COLOR=1 dima_rover
```

普通构建负责必要生成和签名，不隐式执行独立检查。若本轮安排发布验收，再显式执行对应目标，例如：

```powershell
& C:\Users\master\.local\bin\make.cmd NO_COLOR=1 verify
# 仅在需要完整架构审计时另外执行：
& C:\Users\master\.local\bin\make.cmd NO_COLOR=1 check-architecture
```

本指南编写过程只执行了参数和 Metadata 的正式生成入口，没有执行固件构建或上述验收目标。

### 4.2 选择部署方式

**已装兼容 MCUboot 的板**：使用 `build/H743_FreeRTOS_signed.bin` 对应的工程上传流程。车辆保持上锁、动力断开，关闭占用目标端口的 QGC/串口程序；核实端口属于目标板后才上传。

```powershell
# 先把 COMx 替换为设备管理器中已核实的目标板端口；不得原样执行占位符。
& C:\Users\master\.local\bin\make.cmd NO_COLOR=1 upload MCUMGR_PORT=COMx
```

**空板、首次迁移或需要恢复 Bootloader 的板**：使用 `build/H743_FreeRTOS_factory.hex`，按 [MCUboot 与 USB 恢复手册](MCUBOOT_USB_RECOVERY_ZH.md) 通过 STM32CubeProgrammer/ST-LINK 或 ROM DFU 部署。HEX 自带地址；不要把普通应用 BIN 或签名升级 BIN 当成从 `0x08000000` 开始的完整镜像。应用向量表为 `0x08040400`。全片擦除会影响现有持久配置，先做好备份，并按实际恢复目的选择擦除范围。

升级包签名须与板内 MCUboot 信任的密钥匹配。普通应用 OTA 不更新 MCUboot。不要从“上传字节数已到 100%”推断应用已成功运行，应确认目标镜像启动及上传器终态。

### 4.3 QGC 首连

1. 首先用 USB 连接，确认识别为当前 Dima Rover，心跳持续更新，没有反复重启。
2. 等待参数和 Component Metadata 下载完成；在 Parameters 页面按本指南给出的名称搜索。System/Developer 类别参数也可能需要展开查看。
3. 导出整车现有参数，保留原文件。不要首先执行全参数复位或导入其他 PX4/APM 车辆模板。
4. 确认当前是 Manual、Disarmed；确认遥控开关处于安全位置。
5. 检查模式名称。当前用户可选功能包含 Manual、Mission、Auto Calibration；Hold 和 Termination 是内部状态，不能照搬通用 PX4 飞行模式菜单操作。
6. 若 Auto Calibration 显示 Unknown 或列表混入其他飞行模式，先完整断开重连并等待模式目录下载；仍异常则保留 QGC 日志与协议证据。在名称和当前模式未确认前不启动运动。

## 5. 通信、遥控和日志配置

### 5.1 分配物理串口

在 QGC 搜索接线端口的 `SERIALx_FUNCTION`，选择相应的 SBUS、GPS 或 MAVLink。具体编号对应物理 UART/USART 尾号，**不存在 SERIAL5**；USB 使用自身链路，不需要分配一个 UART 给它。引脚与端口说明见该参数的中文 Metadata 和 [SerialConfig 说明](../Dima/modules/serial/README.md)。

必须保留唯一 SBUS owner；需要 GNSS 或数传时，分别分配唯一 GPS/MAVLink owner。默认 SBUS 位于 SERIAL6，但本车必须按真实接线核对。功能迁移可能同时关闭旧 owner，改完后重新读取旧、新端口确认。

`SERIALx_BAUD/FUNCTION` 均需重启生效。SBUS 驱动固定使用 100000 bit/s、8E2、RX 反相；不能靠填普通 UART 波特率解决错误的 SBUS 电气接法。GPS owner 由 UM982 驱动管理，目标为 460800 bit/s，普通 `SERIALx_BAUD` 不直接替代其协议速率合同。

若启用串口 MAVLink，优先把两端明确设置为相同波特率和 8N1；Auto 可探测，但现场首配使用已知速率更容易定位接线问题。`MAV_0_RATE` 是发送预算，不能把低速链路变成高速链路。USB 正常后再验收数传，修改串口功能后统一保存、重启和回读。详见 [MAVLink 双链路说明](MAVLINK_UART_ZH.md)。

### 5.2 完成 Radio 校准与两轴方向检查

1. 保持动力断开、Disarmed，在 QGC Radio 页面按提示完成接收机通道校准，覆盖摇杆两端、中位和使用的开关位置。
2. 将 `RC_MAP_THROTTLE` 指向实际前后杆通道，`RC_MAP_YAW` 指向实际转向通道。默认分别为 1、2，仅在真实接线匹配时保留。
3. 重新读取相应通道的 `RCn_MIN/TRIM/MAX/REV/DZ`。向前杆应产生正纵向输入，向右杆应产生正转向输入；输入不正确时在 RC 域修正，先不动 PWM 侧别。
4. 油门和转向均按中心双向轴使用。两杆自然回中后，输入应稳定为零；当前默认 RC1/RC2 死区为 30 us，旧车保存的零死区不会因升级自动变成 30。换用其他通道后须核对新通道死区。
5. `RC_MAP_PITCH/ROLL` 是当前产品用于 QGC 完成流程的固定兼容标记，不承担本车运动控制，不要为点亮页面虚构额外运动轴。

验收：原始 RC 数据持续更新，中心稳定、端点可达、前后/左右符号正确；接收机自己进入 failsafe 时不能继续发布“健康的旧杆位”。

### 5.3 配置 Arm、Kill 和模式开关

将 `RC_MAP_ARM_SW` 分配给明确的二段解锁开关，并核对 `RC_ARMSWITCH_TH` 对应的开关方向。启动、恢复接收或改映射后的第一次稳定状态只建立基线；必须先 OFF，再明确拨到 ON，才形成解锁请求。

将 `RC_MAP_KILL_SW` 分配给易于触及、不会误拨的独立开关，核对 `RC_KILLSWITCH_TH`。仅填写参数不能证明急停有效，必须完成第 6.4 节检查。

需要遥控切模式时设置 `RC_MAP_FLTMODE`，再配置 `COM_FLTMODE1..6` 的实际槽位。标准三段开关通常落在槽 1、4、6，必须逐位置验证。首轮建议保留清晰可达的 Manual 槽；Mission 和 Auto Calibration 只在对应阶段准备完成后启用。当前生成目录支持 Auto Calibration 选项（值 23），选择它仍要求 Disarmed，且不会自动 Arm；Reserved/Unassigned 不发模式动作。

避免把模式、Arm 和 Kill 同时拨动：同帧安全动作可抑制模式请求。被拒绝的模式请求不会自动重试，纠正条件后应重新执行明确的模式操作。

### 5.4 先把日志录全

首轮调试建议 `SDLOG_MODE=2`，从启动记录到关闭，覆盖解锁前的静态、传感器及标定准备阶段。正常默认 `SDLOG_MODE=0` 只记录 Armed 区间，可能缺少故障发生前的静态证据。

在 `SDLOG_PROFILE` 勾选 General Rover 与 Rover system identification，组合值为 5；若还需要完整 EKF2 replay，可选择三项组合值 7。Profile 修改按 Metadata 要求重启。高数据量配置应先确认 SD 持续写入能力及丢数情况，不能仅检查“文件存在”。

读取 `SDLOG_DIRS_MAX` 并核对剩余空间；重要旧日志先复制归档。重启后做一次短会话并下载检查：文件能解析，参数快照存在，时间轴连续，所需控制/输出/传感器数据实际出现。默认模式下无解锁就没有新 Armed 日志，不应直接判断 SD 故障。

## 6. PWM、电机方向与急停验收

### 6.1 设置真实侧别与中位

在实际接线的 `PWM_Sx_FUNC` 中选择 Motor right（101）或 Motor left（102），至少各有一路；未使用的通道保持 Disabled。例如，**仅当现场确为 S1 接左轮、S3 接右轮**时，才设置 `PWM_S1_FUNC=102`、`PWM_S3_FUNC=101`。不能把既有车辆的接法当作本车必选接法。

对每个已用输出，根据电调资料和实测确定 `PWM_Sx_MIN/CENT/MAX`，严格满足 `MIN < CENT < MAX`。产品接受 500～2500 us 的普通脉宽，默认 1000/1500/2000 us；“合法范围”不代表电调允许使用整个范围。`CENT` 必须是真实停止中位。

当前后端通常为 50 Hz PWM（约 20 ms 周期），应在实际插口测量脉宽、频率和中位，确认电调兼容。先信号测量、后接通动力；不要使用未经本固件支持确认的 QGC 电机测试按钮替代这套步骤。

### 6.2 设置起步输出与反向行为

依据电调、传动和架空验证给 `MOT_THR_MAX` 设置明确的本轮输出上限。这个值是归一化输出，不是 m/s；0.2 表示 20%，不是 0.2 m/s。对一台未知车辆没有通用安全值。

`MOT_THR_MIN` 由本车可稳定起步的最小正向输出确定；当前共同电机整形会把它用于非零轮端命令，并与输出上限、EXPO 等共同决定实际幅值；精确零命令仍保持零，不能认为它只影响前进、不影响倒车或闭环小输出。须满足 MOT_THR_MIN ≤ MOT_THR_MAX。0.15 表示 15%，不能填写 15。它不是遥控死区，也不能用于修复摇杆回中偏差；不要让电机在只抖动、不转动的堵转区长时间通电。修改前先检查轮子、传动及电调状态。

`MOT_REV_DELAY` 决定单轮换向中立等待，当前默认 0.2 s；原地左右互换有短暂停顿可能是这个行为。`MOT_SLEW_RATE` 为归一化输出每秒，0 表示禁用；启用后 Manual 回中也遵守斜率，不等同于立即停波。`MOT_ARM_RAMP` 约束解锁后的输出渐增。先按电调要求保留或配置这些值，再实测停车与换向，不能只看参数数值。

### 6.3 架空方向检查

将油门、转向回中，Manual，动力接通后确认 Disarmed 时两侧均不转。再进行短时、小输入检查，每次异常先 Disarm 或 Kill，确认停止后才改参。

| 操作 | 必须观察到的实际轮向/车头趋势 | 不满足时的处理 |
| --- | --- | --- |
| 小正油门、零转向 | 两侧均驱动车辆前进 | 先核对 FUNC，单侧反向用该通道 REV 修正 |
| 小负油门、零转向 | 两侧均驱动车辆后退 | 检查电调反向模式和等待时间，再查 REV |
| 零油门、小正转向 | 左侧前进、右侧后退，车头向右 | 先确认 RC 转向为正，再核对左右侧别 |
| 零油门、小负转向 | 右侧前进、左侧后退，车头向左 | 同上 |
| 两杆回中 | 两侧真实停止 | 检查 RC 中位/死区、PWM 中位、电调停止区 |

共享差速逻辑的方向约定为 `right = T - S`、`left = T + S`；正转向使车头俯视顺时针。幅值还会受到限幅、整形、换向等待影响，但侧别和符号应一致。倒车时也保持这一车头转向符号，不能按汽车方向盘的倒车习惯推断杆位效果。

`RCn_REV` 修正人的输入方向；`PWM_Sx_FUNC` 决定真实左右侧；`PWM_Sx_REV` 匹配电机安装正反。先把这三件事分别验收，再做自动校准，不能通过同时互换左右与反转遥控掩盖错误。

### 6.4 架空故障动作检查

| 检查 | 操作与通过条件 |
| --- | --- |
| 普通上锁 | 小输出时请求 Disarm，确认进入上锁且有效通道回 CENT，两轮停止 |
| Kill | 小输出时触发 Kill，确认 PWM 停波、电调撤力；恢复 Kill 后仍检查状态并重新人工授权，不以恢复开关作为可开车证明 |
| RC 失联 | 架空小输出，关闭发射机；确认接收机 failsafe/超时使固件 Disarm，输出进入安全状态 |
| RC 恢复 | 开启发射机，确认恢复不会自动解锁；Arm 开关回 OFF 后重新产生 ON 边沿 |
| 数据链断开 | 架空、专人控制 RC，断开 QGC 链路；确认操作员知道它不等同于 RC 失联，不期待自动返航 |
| 重新上电 | 杆位和开关安全、动力受控，确认没有非预期转动，参数和侧别正确恢复 |

任一项未通过，保持架空，排查电调失信号设置、参数应用、输入链和 PWM 实测；不能直接落地“试一下”。

## 7. 传感器、几何与导航基础

### 7.1 先固定坐标系和轮距

测量左右轮中心间距，以米设置 `RD_WHEEL_TRACK`。例如实测 560 mm 应填写 0.560 m；不是轮胎外缘宽度，也不是轮周长。自动校准运动要求轮距大于 0 且不大于 5 m；Metadata 的宽范围不等于该模式接受范围。四轮滑移转向仍先填写真实左右轮距，不能先把它当成修正转向误差的随意系数。

按控制板实际安装姿态设置 `SENS_BOARD_ROT`，按外部磁力计真实安装方向核对 `CAL_MAG0_ROT`。板级细调由正确的水平校准产生，不用任意微调掩盖 90°/180° 装反。车体坐标使用前、右、下（FRD）；轻微抬车头、抬右侧和水平转车，分别检查姿态/航向变化符号。

以一致的车体参考点测量 GNSS 天线与 IMU 位置，填写相应 `EKF2_GPS_POS_X/Y/Z` 和 `EKF2_IMU_POS_X/Y/Z`，单位米，X 向前、Y 向右、Z 向下。不能把世界坐标或两天线间距填入杆臂字段。

### 7.2 基础传感器校准顺序

1. 先设置安装方向，再做校准。动力断开、Disarmed，在 QGC Sensors 中执行陀螺仪静止校准。
2. 按页面完成加速度计六面校准，每个姿态保持稳定。较重车辆应在机械总装前规划可安全翻转的控制器组件；组件最终安装方向必须与参数一致，不能把整车危险翻转当成现场例行动作。
3. 装回并固定到最终位置，在已知水平的平面执行水平校准。坡地静止不等于水平，不能把斜坡记录为车体零姿态。
4. 使用磁力计时，完成该设备的基础校准并确认 ID 匹配、方向正确。当前手动磁校准使用六面采样；大车需要在设计阶段安排可安全完成的标定方式，不能用仅原地转圈替代全部六面尺度标定。
5. 每项等待明确成功及前端应用完成，再进行下一项；保存、重启后核对姿态和校准值。

自动校准会重新做 Level，并尝试 IMU/磁偏置优化；它不替代六面尺度标定，也不负责随意改写设备 ID、安装旋转和 scale。不要手工编造 `CAL_ACC0_*`、`CAL_GYRO0_*`、`CAL_MAG0_*` 的校准结果以绕过检查。

### 7.3 UM982 双天线与 RTK

1. GPS 端口按第 5.1 节分配并重启。确认接收机上电、两天线固定且无遮挡；飞控 SERIAL 编号与 UM982 内部 COM 编号不是同一套编号。
2. 先确认原始位置、速度和航向持续更新，再确认定位质量。看见卫星或 3D Fix 不代表满足自动校准要求。
3. 按 UM982 和现场基站/NTRIP/数传方案建立真实差分输入。本固件当前接收处理目录没有 QGC `GPS_RTCM_DATA` 转发入口，不能只在 QGC 配好 NTRIP 就假定差分已进入接收机；应使用已验证的接收机差分链路。
4. 测量两天线基线，并核对主/副天线身份。`GPS_YAW_BASELINE` 表示基线长度；`GPS_YAW_OFFSET` 表示安装航向偏置。已有可靠值先核对，未知值由本轮 RTK 标定产生，不照搬另一台车。
5. 当前航向换算为 `车体 yaw = wrap(raw heading + 180° - GPS_YAW_OFFSET)`。用已知朝向和小范围手动转车检查符号；不要在 EKF 层再额外重复减偏置。
6. 首次自动校准前等待 RTK Fixed 及双天线固定航向稳定，再进入模式。入场坐标只抓取一次；没定位时先进入，后来定位恢复，不会自动补成完整运动会话，应退出并重新进入。

当前运动质量检查包含：位置 RTK Fixed、双天线解算与整周固定、同历元速度配对、基线 0.1～10 m、航向精度不大于 1°、位置 EPH 不大于 0.15 m、样本新鲜。入场圆心要求 EPH 还须大于 0。RTK 参数应用后的阶段还要求 GNSS yaw 实际融合、新息通过及基线一致；这些数值是源码准入条件，不是通过一次观察即可长期保证的精度承诺。

`EKF2_GPS_CTRL` 的 bit 3 控制双天线航向融合。默认 7 没有该位；自动 RTK 事务会在保留现有位的基础上打开它。已有已验证偏置且手动配置融合时，默认三项加航向组合为 15；不要在偏置方向未知时仅为让状态变绿强行改成 15。自动校准结束后要核对实际融合及保存结果。

QGC 原始 GPS 正常和 EKF 导航就绪是两层证据。GPS 文本汇总在当前驱动中默认由编译开关关闭，缺少 `GPS online` 文本本身不能证明 GPS 离线；以实时遥测与 ULog 为准。

### 7.4 DroneCAN 磁力计（装有时执行）

核对 `UAVCAN1_ENABLE`、`UAVCAN1_BITRATE`、`UAVCAN1_NODE_ID`：CAN 速率必须与外设一致，本机节点号不得冲突；Automatic Node Allocation 要求外设支持并发出标准分配请求。当前默认模式为自动分配、500 kbit/s、本机 ID 1，应逐项核对本车总线。

首轮只连接预期磁力计，确认设备识别正确。驱动自动绑定首个合法磁场来源，当前没有手选磁节点参数；多设备并存不能靠猜测确认绑定对象。SD 不可用可能影响 DNA 持久化并产生存储告警，不等于 CAN 电气故障。

确认静止磁场合理，方向随车辆转动正确，低输出带载时没有明显突变。当前自动磁校准主要优化 offset 和电机干扰补偿，不代表完整 soft-iron 标定。若未安装磁力计，校准应明确报告相应项跳过；使用它参与融合时则必须完成对应标定与带载检查。

## 8. 第一次落地：只做低速手动验收

1. 选择平坦、空旷、无行人车辆交叉的场地，划定人员站位和可用停车空间。操作员持 RC，观察员准备动力断电，双方先约定中止口令。
2. 记录当前输出上限、载荷、电压和轮胎状态；确认本轮日志已开始。车前、车后和转圈范围内无人。
3. 两杆回中，Manual，人工 Arm。先短距离直行、回中停车，再短距离倒车与停车；检查起步是否突跳、停车是否拖行、两侧是否明显不同步。
4. 小输入检查左右转向和低速原地转向，再做前进/倒退组合转向。确认车头响应与第 6.3 节一致，急转时内轮可能反转。
5. 在低速且空间充足的条件下验证实际停车距离和操作员接管能力。不能从架空“轮子停了”推断落地后的滑行距离。
6. 停车、Disarm，查看 ULog。若有回中爬行、抖动、明显打滑或方向不符，先查 RC 归零、输出侧别/极性、电调中位、机械状态和采样证据，再考虑控制参数。

此阶段通过后，才允许自动校准。手动正确不能直接证明自动坐标和定位正确，但手动方向尚未正确时，自动校准没有可用基础。

## 9. 自动校准：场地、步骤和保存判定

### 9.1 必须先定义本轮实验范围

明确设置并回读 `RO_SPEED_LIM`、`MOT_THR_MAX`、`RO_CAL_DIST`、`RO_CAL_RADIUS`；核对 `RD_WHEEL_TRACK` 和本车 RC/PWM 配置。`RO_SPEED_LIM` 必须为有限正值，0 不满足自动运动要求。当前 `RO_CAL_XTE_MAX` 也是有限正值，零不表示“绝对不允许误差”而是无效配置。

首次运行建议从已完成手动验证的低巡航速度开始，但必须再次检查**本轮 `MOT_THR_MAX` 全输出**的车速和停车空间。正式制动观测在去程/返程取得两次证据，包含达到全输出超过约 3 s 的观测过程，可能比普通低速直行需要更长场地。

`RO_DECEL_LIM` 在首次自动校准可为 -1/0，由流程先探测再形成正式结果；不要填一个未经测量的较大减速度来让软件计算出更短停车距离。形成模型后软件使用 `d = v²/(2a)` 估算名义停车距离；现场还需要覆盖通信/控制延迟、坡度、轮胎打滑、车辆外廓和人工中止余量。速度翻倍时，这个模型的距离会变为四倍。

场地必须同时容纳直线往返、掉头、顺逆转动及后续二维路径。软件几何约束只覆盖定位参考点，不能替代围挡和人员隔离；在尚无制动模型时，更不能把软件“允许开始”当作已经证明可在边界前刹停。

### 9.2 启动操作

1. 完成基础传感器校准和手动验收。车辆处于最终测试负载，停在水平开阔场地，GNSS 已稳定 Fixed，车头朝向预留直线区域。
2. 确认日志能覆盖解锁前阶段，保存“标定前”参数备份。关闭其他会自动写参数的客户端。
3. 保持 Disarmed，选择 Auto Calibration；可使用已正确显示的 QGC 模式或已经验收的 RC 模式槽。不要同时请求 Arm 和切模式。
4. 观察本轮会话开始、静态 Level 和基线状态。此时车辆应真实静止；摇晃车体、坡地或陈旧传感器数据会使静态阶段失败。
5. 两杆回中，确认所有运动前提已满足后，明确执行一次人工 Arm。进入模式不会自行解锁；流程推进不要求操作员在每个阶段反复上锁/解锁。
6. Arm 后操作员持续准备 Kill/Disarm，保持 RC 可用。静态和参数应用阶段可能仍显示 Armed，但 PWM 被独立停波锁抑制；之后可能自动继续运动，不能趁暂时不动进入车辆范围。

### 9.3 执行中看什么

按当前会话文本与状态判断，流程包含静态准备、基线采集、直行往返/制动、双天线与动力学辨识、转动/磁场处理、响应采集、增益辨识与闭环验证、可用的导航实验及最终收尾。具体阶段和原因名称由消息工具生成，不另维护编号表。

重点观察实际动作是否合理、是否在预留区域、前进方向是否正确、停止后是否继续漂移、定位和航向是否跳变，以及 `[autocal]` 的当前原因和最终结果。QGC 不一定展示全部内部字段；详细核对使用 ULog，不假设存在专用完整标定面板。

中途不要改 PWM、RC、轮距、安装姿态、巡航限速、输出上限或增益，不同时开启 QGC Sensors/Radio 校准。会话冻结入口配置并核对参数代次，外部写入可能使候选失效并触发回滚。

### 9.4 中止与失败

遇到方向不符、明显偏离、传感器跳变、危险加速或机械异常，立即用已验证的 Disarm/Kill；必要时动力断电。人身和设备安全优先于保存本轮结果。

真实 Disarm、切出模式或安全故障会取消/终止当前会话，**不是暂停后继续**。再次进入会从 Preflight/Level 重新执行，不继承上一轮完成位。制动失败、速度验证失败等路径会停在原地，不应预期它继续自行返场。

普通组失败可能保留其他已确认成果，硬故障、取消等按会话策略回滚；不能简单断言“失败必定一个参数没改”或“做过的阶段都保存了”。等待收尾，导出实际参数并与前一份比较。

### 9.5 成功、部分完成与重启复查

1. 等待 FINALIZE 完成，确认车辆 Disarmed 且会话已退出，记录最终结果和原因。当前收尾会先请求 Commander 上锁，再进行保存/回滚，结束后返回 Manual。
2. 运行中的 provisional/RAM 候选、进度条或一个阶段成功，不是已经持久化。最终保存成功后才登记 completed；不能在还处于 FINALIZE 时拔电作为正常结束方法。
3. `SUCCESS` 也需要检查哪些导航项被明确跳过。可选 IMU 项未完成不一定否决整体结果，导航项目允许按实际条件跳过；这不等于本车已通过全部 Mission 工况。
4. `PARTIAL` 表示应核查已保存的有效组及缺失组，不直接投入自动任务。`FAILED/CANCELLED` 必须结合原因、回滚状态和参数回读判断。
5. 若报存储/前端确认/回滚故障，保持上锁，保存日志，检查 SD、Flash 存储状态及参数一致性，不用强制解锁绕过锁存。
6. 导出“标定后”参数，正常重启后再次导出，核对实际需要保留的结果确已恢复，再做短距离手动检查和低速自动验证。

更换电调、供电体系、传动、轮径、载荷或显著修改输出整形/上限后，原动力学结果不能自动视为仍适用。降低上限完成一轮标定后再大幅提高输出，同样需要重新确认相关能力与停车距离。

## 10. Mission 前必须成立的控制配置

这一步核查**校准结果是否完整且适用**，不是要求操作员凭经验硬填全部增益。

速度内环需要 `RO_MAX_THR_SPEED` 为有效正值，`RO_SPEED_P/I` 非负且不能同时为零，`RO_ACCEL_LIM` 与 `RO_DECEL_LIM` 为正。`RO_MAX_THR_SPEED` 是等效前馈系数，不等于物理极限速度，不用它取代巡航速度设置。

转向内环需要有效轮距、正的 `RO_YAW_RATE_CORR`，`RO_YAW_RATE_P/I` 非负且不能同时为零；`RO_YAW_RATE_LIM`、`RO_YAW_ACCEL_LIM`、`RO_YAW_DECEL_LIM` 必须为正。外环还需要正的 `RO_YAW_P`，合理且有序的 `PP_LOOKAHD_MIN/MAX` 与正的 `PP_LOOKAHD_GAIN`。

正常导航还要求正的 `RO_JERK_LIM`、合理的 `NAV_ACC_RAD`、正的 `RO_SPEED_LIM`，以及 `RO_SPEED_TH < RO_SPEED_LIM`。当前运行校验对部分限制的要求比 YAML 中“允许 -1”更严格；不要依据参数写入成功就认定导航配置有效。

转向滞回要求 `RD_TRANS_DRV_TRN > RD_TRANS_TRN_DRV > 0`；这两个阈值是 rad，而 `RO_YAW_RATE_TH/LIM` 是 deg/s。还要求角速度死区小于角速度上限，并满足：

```text
RO_YAW_RATE_TH × π/180 < RO_YAW_P × RD_TRANS_TRN_DRV
```

左侧换算为 rad/s，右侧是航向控制器在“转向退出角”处请求的 rad/s。若死区先把这个请求归零，车辆可能停在退出角之外而无法继续行驶。出现原地转动后不走，先核对这一组合与日志，不能只放大转向退出角。

最终以当前控制器应用状态和短程实车闭环响应为准。缺少导航校准项时，先补足该组验证或进行有证据的人工整定；不得把增益设为任意正数只为获得 parameters_valid。

## 11. 第一个自动任务

### 11.1 编制与回读

1. 在 QGC Plan 中建立平坦开阔区域内的 2～3 个简单普通航点；第一个航点应位于已观察到的车辆真实位置附近，整条路径包含明确停车余量。
2. 当前任务容量为 64 项，接收普通 `NAV_WAYPOINT`。不要加入起飞、降落、RTL、DO_CHANGE_SPEED、复杂动作、指定航点朝向或悬停等待等通用飞控命令。
3. 航点到达半径可单独设置；未给有效正值时使用 `NAV_ACC_RAD`。等待时间和穿越半径保持默认零/未指定，yaw 保持未指定，autocontinue 开启。高度需要协议上有效，但不是给地面车规划越障动作的接口。
4. Disarmed 时上传，等待明确成功；再从车辆下载任务，逐点比较数量、位置、顺序和当前入口。地图上本地画好路径不等于车辆已收到。
5. 使用 SD 时确认任务存储正常；无 SD 的成功上传可能只保存在 RAM，重启后会丢失。更换 SD 也可能恢复那张卡的旧任务，因此每次启动均重新核对车辆内任务。

### 11.2 执行与接管

1. 确认控制配置完整、估计器健康、当前任务正确，日志记录中，RC 及 Kill 可用。
2. 两杆回中，在 Manual 人工 Arm，然后明确请求 Mission。当前进入 Mission 需要 Armed、已提交任务和估计器就绪；请求被拒绝时先处理原因，再重新操作。
3. 观察真实起步、直线跟踪、转弯、末端减速和停车。进入 Mission 的界面状态本身不能证明控制参数有效或实际输出已允许。
4. 若需接管，保持杆位安全并切 Manual，确认模式反馈后按手动方式控制；需要立即终止时使用已验证的 Disarm/Kill。不要把拉动油门杆当成当前系统保证的自动模式退出机制。
5. 到最后航点后确认实际停止及终态，再 Disarm；不假设完成任务会自动返回出发点。
6. 下载日志，比较实际轨迹、速度、转向与停车效果。首轮通过后才逐步增加任务长度、转弯幅度、速度、负载或地面复杂度，每次只改变能解释的一组条件。

软件当前没有因 QGC 断连自动 RTL 的保障，自动校准的范围约束也不是 Mission 的通用避障/围栏功能。Mission 必须在操作员持续监督和可接管的环境中运行。

## 12. 常见现象与现场处理

| 现象 | 优先核对与下一步 |
| --- | --- |
| QGC 参数缺失或描述陈旧 | 核对板端固件身份，等待 Metadata 下载，重连后搜索；不要补写旧参数名 |
| Manual 解锁后立即上锁/没有动力 | 查 RC 新鲜度、接收机 failsafe、Kill、PWM 合法配置、执行器状态及维护/存储忙原因 |
| 松杆后慢慢爬行 | 比较 RC 回中值与死区，再测 PWM CENT 和电调停止区；不要先增大电机零阈值 |
| 前进变旋转或左右相反 | 从车尾视角核对 FUNC；确认 RC 符号与每侧 REV，分别验证后再组合 |
| 单轮只抖不转 | 先查堵转、传动、电调和供电，再测最小可持续起步输出，避免长时间维持抖动 |
| GPS 有卫星但自动校准不动 | 区分 RTK 位置固定、双天线固定航向、同历元速度及 EKF 融合，不凭卫星数判断 |
| 进入校准后只有 Level/部分完成 | 查入场是否已固定定位、轮距和实验配置；退出后在条件满足时重新进入 |
| 正式制动前很快就报空间不足 | 全输出观测需要加速、稳定和停车距离；降低本轮可接受输出或换更大场地，再重新准备，不降低质量门槛 |
| 报 braking observations=0、decel=NaN | 没有形成有效制动证据，不能据此断言机械刹车弱；对齐运动阶段、后端输出、速度历元和停车确认 |
| 校准 Armed 但轮子不动 | 先判断是否静态/提交停波窗口及当前就绪条件，不绕过停波锁；流程随后可能自动运动 |
| Mission 显示成功切入但不动 | 查已应用控制参数、请求有效性和执行器状态；模式切换门与控制有效性是不同条件 |
| 一直原地转、难以切回直行 | 核对真实方向、航向/角速度、转向滞回和第 10 节死区关系 |
| 参数回显正确但重启恢复旧值 | 查最终保存结果、unsaved/存储错误、SD 可用性；不要用不断重复写同一值替代定位 |
| SD 日志缺头、缺终态或文件增长慢 | 查日志模式、记录 Profile、可用空间、实际丢数和文件关闭状态，先保留原始文件 |
| 数据链断开车辆仍继续 | 当前没有 GCS loss 自动导航动作；由 RC 接管或 Disarm/Kill，不能等待不存在的 RTL |

排查时按“物理现象 → 输入 → 运动请求 → 后端接受输出 → 传感器测量 → 状态/原因”对齐时间。后端记录的已接受 PWM 命令仍不能替代引脚测量、真实轮向或电流证据；不要从一条状态推断整条物理链路。

## 13. 每次运行与收车清单

### 出车前

- [ ] 电源、线束、轮胎、传动、天线和传感器固定正常；测试负载与标定条件相符。
- [ ] 本次固件身份、参数版本、车辆内任务已核对，上一轮故障已处理。
- [ ] RC 连续有效，Arm/Kill/Manual 位置明确，摇杆回中，急停与断动力装置可用。
- [ ] 电调中位无爬行；近期改过接线/REV/RC 映射时已重做架空方向检查。
- [ ] 自动运动所需 RTK、航向和估计器健康已稳定，安装姿态及几何正确。
- [ ] SD 可用且有空间，当前日志模式和数据集能覆盖计划动作。
- [ ] 已检查场地、人员站位和停车空间；自动校准时单独核对全输出制动风险与直线范围。

### 收车时

- [ ] 确认实际停车、Disarmed；关闭电机动力。
- [ ] 若刚结束自动校准，已看到 FINALIZE 的最终结果且没有保存/回滚故障。
- [ ] 等待日志和存储操作完成，再按设备正常停机方式关闭控制器；不带电拔正在写入的 SD。
- [ ] 保存 ULog、参数导出、任务及现场动作记录，标注“通过/未通过/未执行”。
- [ ] 存在未解决的方向、制动、定位、存储或失联问题时，登记为禁止自动运行，避免下一位操作员误用。
